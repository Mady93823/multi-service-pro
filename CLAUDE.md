/# UrbanServe — Urban Company–style Home Services Platform

Client project. 3 roles (Customer / Provider / Admin), Laravel backend, live provider tracking, web-installer deployment.

## Source of truth

Read `docs/internal/00-Overview.md` first — it links the full doc set (architecture, modules, tech stack, DB schema, tracking spec, roadmap, conventions). The client-approved scope lives in `docs/client/Requirement-Analysis.md`.

## Hard constraints (client-mandated — never substitute)

- Backend: **Laravel 12** (PHP 8.3+), MySQL 8
- Frontend: **Inertia.js v2 + React 19 + TypeScript + shadcn/ui + Tailwind v4** — UI blocks researched via **shoogle.dev**
- Live tracking + realtime: **Laravel Reverb WebSockets + HTML5 Geolocation + Leaflet + OpenStreetMap** — no Node.js (client hosting ruled it out, ADR D11); single Laravel deployable
- Firebase: FCM push + optional phone OTP only (app must run with Firebase unconfigured)
- Payments: **Razorpay default** (UPI-first, INR, GST invoicing), Stripe secondary, pay-after-service enabled
- Must stay **easy installable** (web installer wizard) and **easy expandable** (domain events + settings flags + API-first)
- **White-label product rule (CodeCanyon build):** zero hardcoded branding/strings — settings + theme tokens + translation files (ADR D8–D10). Client-facing docs never mention resale.

## Working rules

- Follow build order in `docs/internal/06-Roadmap.md`; don't skip phase gates
- Code conventions, folder layout, and quality bar: `docs/internal/07-Conventions.md` (Actions pattern, thin controllers, Pest tests, Larastan L6, strict TS)
- Booking status changes only via `BookingStateMachine`; money columns are snapshots; ledgers append-only (`docs/internal/04-Database-Schema.md`)
- Scope/tech changes: update client doc + internal docs in the same commit; record decisions as ADR entries in `docs/internal/03-Tech-Stack.md`

P7.1 security & hardening pass done (2026-07-15, ADR D37) — no new tables; the finding of the milestone is that **every real hole was outside the request a policy sees**. (1) **`App\Support\UploadRules` is the one allowlist** — ten form requests each carried their own `mimes:jpg,jpeg,png,webp`; an arch test now fails any FormRequest that spells a mime list by hand. (2) **`App\Http\Concerns\ServesPrivateFiles`** — a policy decides *who* may read a private file, this decides *what the browser may do with it*: images inline, **everything else `Content-Disposition: attachment`**, always `nosniff` (KYC/receipts/attachments accept PDFs, and a PDF served inline from our own origin is a script host). (3) **`config/filesystems.php` local disk `'serve' => false`** — the starter's default registers `GET /storage/{path}` **and (Laravel 11+) `PUT /storage/{path}`** straight into the private disk, signature-gated rather than policy-gated: a second door no `BookingPolicy` has a say over. Closed; a test asserts both route names are gone. (4) **`SecurityHeaders` is a GLOBAL middleware, not a `web`-group one — this is load-bearing: `auth` sits in Laravel's middleware *priority* list, so it is sorted AHEAD of anything appended to a group, and an unauthenticated request redirects out before a group middleware ever runs.** A `web`-group header middleware therefore never touches a login redirect, a 403, a 404 or a 500. Headers: `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, and `Permissions-Policy` keeping **`geolocation=(self)`** (M07's journey screen reads GPS — withholding it kills live tracking silently); HSTS only on a secure request in production. **No CSP yet, deliberately** (D26's custom JS + M24's analytics IDs would force `unsafe-inline`). (5) **Rate limits swept, not sampled:** named limiters in `AppServiceProvider::defineRateLimiters()` (`auth` per IP, `uploads` per user, `public-write` per IP) + `RateLimitTest` **fails any state-changing route reachable without a session that carries no throttle** — that is the class that gets forgotten. Register/forgot/reset are 5/min; login keeps LoginRequest's per-email lockout with `throttle:auth` as the wider per-IP net. (6) **`SecretExposureTest` derives the credential list from the KEY NAMES** in `SettingsRegistry::defaults()` (`/secret|password|_token|auth_key|credentials/i`), writes a sentinel into each, renders all 24 settings screens and asserts the sentinel appears in none — so a settings group added later is covered without being told about; the public halves (`razorpay_key_id`, `stripe_publishable_key`, `recaptcha.site_key`) must still render. (7) Webhook replay pinned for **both** gateways (one payment row, one `BookingPlaced`, one status-history row). 17 new tests (762 suite-wide, 4338 assertions).
